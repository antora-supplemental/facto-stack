= Changelog

== 2026-10-24 - v0.2.68 pack release (glossary v0.1.2)

* **v0.2.68** - adds `@antora-supplemental/glossary` @ `v0.1.1` to hub and demo profiles (after link-registry). Term pages under `glossary/` get a generated letter index and whole-word highlights across the site, and every build exports `glossary.json`. Pack key `glossary: { imports: [...] }` pulls in another site's terms so a private site can highlight public ones. Does nothing on sites with no glossary pages.

== 2026-10-23 - v0.2.67 pack release (link-registry v0.1.1)

* **v0.2.67** - pins `@antora-supplemental/link-registry` **v0.1.1**: the extension now receives its `registry` option, and literal warnings use each component version's own `antora.yml` names (no cross-component false warnings).

== 2026-10-23 - v0.2.66 pack release (link-registry v0.1.0)

* **v0.2.66** - adds `@antora-supplemental/link-registry` @ `v0.1.0` to hub and demo profiles (after related-docs). Warns at build time when a page writes a registered `{url-...}` link literally and publishes `_/link-registry/index.json`. Pack key `linkRegistry: { registry: ./docs/link-registry.adoc }`.
* **Workflow template** - `examples/workflows/build-and-deploy.yml`: a fast `links` job (sparse checkout, no install) runs on every push to every branch and every PR; `build` and `deploy` declare `needs:` so a failing scan stops the Antora build and Pages deploy from starting.

== 2026-10-23 - v0.2.65 pack release (related-docs v0.1.0)

* **v0.2.65** - adds `@antora-supplemental/related-docs` @ `v0.1.0` to hub and demo profiles (after page-edit). It links every page to the org's other docs sites through a generated registry page. Configure with pack key `relatedDocs: { sites: [...] }`; set `relatedDocs: { sites: none }` when the org has no other docs sites. Unconfigured: hidden, one info log line.

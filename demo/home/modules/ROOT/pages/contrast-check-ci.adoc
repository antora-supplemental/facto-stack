== Why

Facto ships the Valentus theme with several color schemes, and your own paint or supplemental CSS can break contrast in one scheme while the others look fine.
`contrast-check` loads your built site in Chrome once per color scheme the paint declares and reports WCAG AA failures as errors and near misses as warnings, each with a suggested color.

`contrast-check` is *not* part of Facto and is not a Facto dependency.
It is a build-time test from the `antora-ui-chassis` monorepo (`packages/contrast-check`), so you add it to *your* CI, after your Antora build.
Full reference: {url-cc-docs}[chassis contrast-check docs] and the {url-cc-readme}[package README].

== GitHub Actions

Run the Action on the built site.
Leave `schemes` empty to check every scheme in the paint's manifest.
GitHub-hosted Ubuntu runners already have Chrome.

[source,yaml,subs=attributes+]
----
jobs:
  contrast:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: "20"
      - name: Build Antora site
        run: |
          npm install
          npx antora antora-playbook.yml   # writes build/site
      - name: Contrast check (every color scheme)
        uses: antora-supplemental/antora-ui-chassis/packages/contrast-check@{cc-tag}
        with:
          site: build/site
          pages: "index.html,**/*.html"
          max-pages: "50"
          schemes: ""            # empty = every scheme the paint declares
          fail-on: none          # report only; move to warning, then error
          suppress: contrast-check.suppress.yaml   # optional
          show-suppressed: "true"
          json: contrast-check.json
----

Inputs: `site`, `pages`, `max-pages`, `schemes`, `paint`, `config`, `fail-on`, `suppress`, `show-suppressed`, `fail-on-stale`, `json`, `args`.
The step writes `::error` / `::warning` annotations and a summary table to the job summary, and the JSON report path is the `report` output.
`config` defaults to `./contrast-check.config.json` when that file exists.

== Other CI (GitLab CI and others)

The CLI needs Node.js 20 or later and Chrome or Chromium.
It finds `/usr/bin/google-chrome`, `/usr/bin/chromium` or Chrome on Windows; otherwise set `CONTRAST_CHECK_CHROME` to the browser path.

=== Install from the git tag

The package installs straight from the chassis git tag; it does not need the npm registry entry.
Add it to your site's `devDependencies`:

[source,json,subs=attributes+]
----
"devDependencies": {
  "@antora-supplemental/contrast-check": "github:antora-supplemental/antora-ui-chassis#{cc-tag}&path:packages/contrast-check"
}
----

Or check out the tag and run the CLI from the checkout, the way the GitHub Action does:

[source,sh,subs=attributes+]
----
git clone --depth 1 --branch {cc-tag} {url-cc-repo}.git .contrast-check
(cd .contrast-check/packages/contrast-check && npm install --no-save --omit=dev --ignore-scripts)
node .contrast-check/packages/contrast-check/bin/contrast-check.js build/site --fail-on none
----

=== GitLab CI example

[source,yaml,subs=attributes+]
----
contrast-check:
  stage: test
  image: node:20
  before_script:
    - apt-get update && apt-get install -y chromium
  script:
    - npm install
    - npx antora antora-playbook.yml
    - npx contrast-check build/site --pages "index.html,**/*.html" --max-pages 50 --fail-on none --json=contrast-check.json
  artifacts:
    when: always
    paths: [contrast-check.json]
----

Common flags: `--pages <list>`, `--max-pages <n>`, `--schemes <ids>` (default every scheme), `--paint <file.css>`, `--config <file>`, `--suppress <file>`, `--show-suppressed`, `--fail-on-stale`, `--json=<file>`, `--quiet`.
Exit codes: 0 clean (under `--fail-on`), 1 failed, 2 usage or setup error.

== Roll out with --fail-on

[cols="1,3"]
|===
| `--fail-on none` | Report only; never fails. Start here to see the findings.
| `--fail-on warning` | Fails on any finding (same as `--strict`). Use when warnings are close to zero.
| `--fail-on error` | Fails on WCAG AA errors only. The default; the usual end state.
|===

A practical order: `none` while you fix or suppress the first report, then `error` to gate merges.
Move to `warning` only if you also want near misses to fail.
The config key `failOn` sets the same thing.

== Config and suppressions

Put `contrast-check.config.json` in the directory the check runs from (it is picked up by default), or pass `--config` / the `config` input.
Unknown keys are an error.
A `suppress` entry accepts a known finding: `reason` is required, and after `expires` (`YYYY-MM-DD`) the entry is ignored and reported as `suppression-expired`.

[source,json]
----
{
  "pages": ["index.html", "**/*.html"],
  "maxPages": 50,
  "failOn": "error",
  "failOnStale": false,
  "suppress": [
    {
      "rule": "color-contrast",
      "selector": ".search-input::placeholder",
      "scheme": ["dark"],
      "reason": "Placeholder text, not content; tracked in #42",
      "expires": "2027-03-31"
    }
  ]
}
----

An entry that matches nothing is reported as `suppression-stale`; add `--fail-on-stale` (`failOnStale: true`) to fail on stale or expired entries.
Prefer `suppress` over `ignore`, which drops findings silently.

=== Inline opt-out

Mark an element (or an ancestor) in your templates or content:

[source,html]
----
<nav class="api-nav" data-contrast-check-ignore="focus-not-visible hover-no-change">
----

The value lists rule ids, aliases or globs; an empty value suppresses every rule.
These show as suppressed by `inline`.
Paint and token findings have no element and need a `suppress` entry.

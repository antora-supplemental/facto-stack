= Changelog

== 2026-11-08

=== v0.5.1 bounded source-only contrast sampling

* Fix source-wide expansion: navigation, images, UI/theme and preprocessor edits use representatives, not every page. Follow only direct source changes and transitive include dependents; preserve new-page coverage and explain each selected path.
* Contrast Check 0.4.2 enforces a configurable ten-minute total audit deadline; incomplete audits fail and never advance the successful baseline.

== 2026-11-07

=== v0.5.0 source-aware contrast checks

* Contrast Check 0.4.1: one summary line and GitHub notice per exempted rule; per-rule JSON counts.
* Source-aware contrast sampling checks all changed/new pages plus representative layouts and configured extension pages. Successful baselines track each content source independently; unknown bases use a deterministic broad fallback.
* Link Validator 0.2.3 verifies a HEAD 404 with GET before declaring a page broken.
* Restore the paint/chrome links in the demo's head-styles override for Valentus 4.3.2.

=== v0.4.3 exempted findings in the log

* **Contrast check** - pins `@antora-supplemental/contrast-check` `contrast-check-v0.4.0`: exempted (suppressed) findings are listed as info lines per suppression entry (id, expiry, reason, counts, examples), as `::notice` annotations and in the step summary. Pack key `contrastCheck.exempted` (`summary` default, `all`, `none`).
* **Report file** - the JSON report is kept at `build/contrast-check/report.json` by default (was a temp file), and the closing line names it.
* **Summary line** - "reported only" now says how many are unexempted errors and warnings and how many were exempted.
* **Gating fix** - a finding merged across light and dark scheme runs (`schemes: [light/light, dark/dark]`) now counts as dark for `failScope: dark-and-states`; before, such dark-mode errors (for example `focus-not-visible` in both schemes) were reported only.
* **Suppressions** - removes the stale `facto-nav-tree-filter-control-boundary` (it matched nothing on any site).

== 2026-10-28

=== v0.4.2 contrast fixes at the source

* **page-context** - pins `@antora-supplemental/page-context` `v0.7.3`. The source line under a page now gets the page-context text tokens (it fell back to 3.92:1 in dark mode), and the muted text is opaque, so the source label, byline, time and table headers pass 4.5:1 in both modes.
* **Contrast check** - pins `@antora-supplemental/contrast-check` `contrast-check-v0.3.1`. The focus check judges the strongest focus indicator instead of the first one found, so a solid accent border next to a faint halo is no longer a failure.
* **Suppressions** - removes `facto-nav-tree-filter-focus-indicator`; the site-nav-tree filter's accent border change passes on its own. The two `control-boundary` suppressions stay.
* **Demo bundle** - `demo/playbook.yml` loads Valentus `v4.3.2` (paint slot in `head-styles.hbs`, so a hub's own `head-meta.hbs` override no longer drops the paint; solid search focus ring; `--adt-*` fallbacks).

== 2026-10-27

=== v0.4.1 search box corners

* **Search box corners** - pins `@antora-supplemental/antora-search-chat` `v0.1.26`. The square wrapper around the rounded search box no longer paints the search surface color, so it stops showing in the box corners in light and dark mode.


=== v0.4.0 built-in contrast check

* **Built-in contrast check** - Facto now depends on `@antora-supplemental/contrast-check` (`contrast-check-v0.3.0`) and runs it after every build on the published site, across every color scheme, with the search results open (`search-results` and `fixtures` states). By default the build fails only on WCAG AA errors in dark mode or ones a dynamic state introduces; everything else (light-mode static pages, warnings) is reported without failing. `maxPages` defaults to 20. Per-site override with pack key `contrastCheck` (`false`, `failOn`, `failScope: all`, `maxPages`, `schemes`, `states`, suppressions); env `FACTO_CONTRAST_CHECK=0` skips it. In CI a missing Chrome is an error. See xref:ROOT:contrast-check-ci.adoc[Contrast check in CI].
* **Search dropdown in dark mode** - pins `@antora-supplemental/antora-search-chat` `v0.1.25`, which gives the Lunr result dropdown dark-mode ink (component header, document title, section title and highlights were 1.04-1.59:1, now 6.88-14.64:1). Light mode is unchanged.
* **Default suppressions** - `lib/contrast-check.suppress.json` accepts three known findings until 2027-01-31: the `#search-input` boundary and the site-nav-tree filter field's boundary and focus ring. Fixing them changes light mode; they are follow-ups.
* **Demo bundle** - `demo/playbook.yml` loads Valentus `v4.3.1` (current breadcrumb no longer underlined).

=== v0.3.0 pack release (Valentus 4)

* **Valentus 4** - the demo uses the Valentus **4.2.2** release bundle (`v4.2.2`, was `v3`). `antoraRegistry.requires` is `valentus-theme >=4` and `uses` is `valentus-layout-markup >=4`. Valentus 4 moved light/dark mode to the chassis, so hub and demo profiles now load `@antora-supplemental/light-dark-mode` (`light-dark-mode-v0.1.3`, `toggle: placed`, pack key `lightDarkMode`) after chassis-compose. The demo footer override keeps the new `light-dark-footer-slot`, and the demo `site-themed-svg.css` override restores the Valentus 4 host layout rule. See xref:changelog-details/history/2026-10-26-valentus-4.adoc[History: move to Valentus 4].
* **Registry contracts** - `antoraRegistry.uses` declares `valentus-layout-markup`, so the registry links Facto to Valentus by contract.

* **Changelog moved into the docs** - the changelog now lives in the demo `home` component `changelog` module (`demo/home/modules/changelog/pages/index.adoc`) and is in the nav; the root `CHANGELOG.adoc` is removed. Detail and history pages go in `changelog-details/` beside it. See xref:changelog-details/history/2026-10-26-changelog-moved-into-docs.adoc[History: changelog moved into the docs].
* **Contrast check docs** - new demo page `home::contrast-check-ci.adoc` shows how to add the antora-ui-chassis `contrast-check` (`contrast-check-v0.2.0`) to your own CI: a GitHub Actions job, GitLab/plain CLI installed from the git tag, a `--fail-on` rollout, and a config with a suppression. `contrast-check` stays out of Facto's dependencies.
* **Facto logotype** - `assets/brand/facto-logotype.svg` is the source: outlined "Facto" letters cut into seven bars by an editable pattern mask, over an orange base bar. `node scripts/export-logotype.mjs` exports `facto-logotype-light.png` and `facto-logotype-dark.png` (1600 px); `--bars`/`--gap` change the bands. The README shows the light PNG and links the SVG, and `antoraRegistry.previews` lists both PNGs with an `svg` field naming the source. Replaces the unsliced light/dark logotype files.
* Package description now states only the main behavior in full sentences. The optional Kroki rendering moved to `antoraRegistry.longDescription`, shown as the full description in the extension registry.

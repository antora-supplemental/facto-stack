= facto-stack
:description: De-facto Antora playbook composition — Valentus UI plus search, math, diagrams, and page-context metadata. Not Valentus core.

*facto-stack* (`@antora-supplemental/facto-stack`) is the **compose pack** for a sensible Antora site stack.
Register it once in the playbook — it is a real Antora extension that loads the member stack internally so footers list the pack, not every bundled package:

[source,yaml]
----
antora:
  extensions:
    - require: '@antora-supplemental/facto-stack'
      pageContextAntora:
        component: docs
        path: keywords
----
It documents and templates what DevCentr / antora-supplemental already reuse together:

* **Valentus** UI bundle (`v2` rolling tag) — lean theme only
* **Incremental** (`@antora-supplemental/incremental`) — dependency manifest + dirty-set helpers for faster local rebuilds (hub/demo profiles register it before Lunr)
* **Lunr** (`@antora/lunr-extension`) — site search
* **Search / Ask omnibox** (`@antora-supplemental/antora-search-chat`) — Valentus header tabs on top of Lunr (Ask stub until `searchChat.backend_url` is set on the pack)
* **Emoji** — `@antora-supplemental/asciidoctor-emoji-literals` (interim: pasted Unicode → `emoji:name[]`) + official npm `asciidoctor-emoji` 0.5.x (Twemoji for `emoji:name[]` macros). Drop literals when upstream 1.x runs on core 4.
* **Unversioned component URLs** (`@antora-supplemental/unversioned-component-urls`) — bare `/component/` is a version chooser for numbered components (`mode: selector`)
* **STEM / KaTeX** — `stem: latexmath` (+ supplemental math JS/CSS until in-bundle)
* **Kroki diagrams** (`asciidoctor-kroki`) — Mermaid + PlantUML → SVG at build time
* **Theme-aware diagram SVGs** (recommended compose, not forks) — post-process Kroki/renderer SVG with https://github.com/dev-centr/mermaid-svg-css-vars[`@dev-centr/mermaid-svg-css-vars`] and https://github.com/dev-centr/plantuml-svg-css-vars[`@dev-centr/plantuml-svg-css-vars`] into https://github.com/dev-centr/themed-svg[Themed SVG] adaptive + host artifacts; serve with a `[.themed-svg]` image role so the site dark-mode toggle can recolor host-inlined figures. Raw Kroki `<img>` embeds stay fixed-color.
* **Page context** (`@antora-supplemental/page-context`) — audience / author / rights metadata from `page-*` attributes
* **Article zones** (`@antora-supplemental/article-zones`) — after compose, move page-context lead from `[data-zone="body"]` into `[data-zone="meta"]` (Valentus 3.0.2+ zoned `article.hbs`; register before page-edit and linkinator)
* **Page edit** (`@antora-supplemental/page-edit`) — bake View|Edit Source line into the header zone when zoned (legacy: under the title in flat `article.doc`)
* **Related docs** (`@antora-supplemental/related-docs`) - slim top/footer link to a generated registry page of the org's other docs sites (team, partners, ...). Pack key `relatedDocs: { sites: [...] }`; `relatedDocs: { sites: none }` states there are none. Unconfigured: hidden with one info hint.
* **Link Validator** (`@antora-supplemental/link-validator`) - outbound http(s) checks + triage page (core CLI: asciidoc-link-validator)
* **Link-inator** (`@antora-supplemental/linkinator`) - click-time validity chrome + Wayback button
* **Extension Lister** (`@antora-supplemental/extension-lister`) - footer / purpose / layer listing of installed supplemental extensions
* **Orphan Finder** (@antora-supplemental/orphan-finder) - unresolved xrefs / orphan pages triage
* **Maint CLIs** (optional scripts): nav-drift, stale-page, playbook-pin-auditor, deep-link-contracts; shared UX via triage-ux-kit
* **Build stack footer** (`@antora-supplemental/build-stack`) — publish playbook extensions + UI bundle to `site.keys` for footer attribution
* Optional neighbors: **site-nav-tree** (multi-component sidebar forest with an **`include` allowlist**; keeps default nav-tree)
* **Hub profile footer:** default `profile: hub` registers members internally and keeps the footer at depth 1 (`facto-stack` only). Set `footerListMembers: true` (demo profile default) to list every member instead.
* **Local content sources** (`@antora-supplemental/antora-local-content-sources`, v0.2.34+) — registered *before* other pack members so one committed playbook (GitHub remotes) rewrites to local clones via `.antora-source-id` markers (`mode: auto`, off in CI). Override: `localContentSources: { … }` or `localContentSources: false`.
* **Hub GitHub topics:** playbook repos that use this pack as their provider carry topic `facto-stack` only — not topics for the Valentus UI bundle, nor for any member extension (page-context, site-nav-tree, soft-nav-page-toc, linkinator, page-edit, antora-search-chat, …). link:https://docs.antora-supplemental.org/docs/hub-github-topics/[Hub GitHub topics^].
* **Optional diagram chrome (hub):** `mermaidClient: { enabled: true }` and `diagramLightbox: { enabled: true }` turn on `mermaid-client/antora` and `diagram-lightbox` for hubs whose `supplemental-ui` already includes the Mermaid / lightbox partials.
* Playbook default: `urls.html_extension_style: indexify` (folder URLs; `index.adoc` → trailing-slash path)

Wiring a product repo under `content.sources` publishes pages and xrefs — it does **not** mean the component belongs in the sidebar forest. Thin tools: hub portal under `home` only, or register the source but omit it from site-nav-tree `include`.

=== Hub component naming

Dev-Centr org hubs name the aggregator component `home` / title `Home`, set `site.start_page: home::index.adoc`, and lead the hub nav with **Overview** (portal-branded H1 on the index page). Playbook sources still use `start_path: docs` per repo — do not name the hub component `docs` when GitHub Pages or `site.url` already lives under `/docs` (avoids `/docs/docs/` URLs). Convention write-up: link:https://docs.devcentr.org/home/publishing/hub-home-component.html[Hub home component^] (skill `hub-home-overview` in `dev-centr/agent-rules`).

== Recommended pairing (multi-component hubs)

**nav-typology is optional on its own** — you can use typology icons without site-nav-tree.

When you **do** enable `@antora-supplemental/site-nav-tree`, also ship:

* **Nav filter** — the pack member defaults to `filter: true` (sticky sidebar label filter + UI injection from site-nav-tree **v0.5.4+**). Compose pack: `siteNavTree: { enabled: true, include: [home, …] }`. Explicit playbook require: add `filter: true` (or omit only if you copy `ui/` manually and want no filter).
* `@antora-supplemental/nav-typology` @ `v0.1.12+` (companion UI injects at build time; no manual `supplemental-ui` copy)
* `@antora-supplemental/nav-typology-diataxis` when the hub follows Diátaxis nav buckets

Register typology **after** site-nav-tree. Detail: https://github.com/antora-supplemental/site-nav-tree[site-nav-tree] and https://github.com/antora-supplemental/nav-typology[nav-typology] READMEs.

== What the pack provides to a hub

Hubs should declare **`@antora-supplemental/facto-stack` plus `antora`** in `package.json` — not each member. The pack lists the members as its own `dependencies`, loads them for the Antora `antora.extensions` list, and merges the AsciiDoc extensions and attributes into `playbook.asciidoc`. Under pnpm the `antora` shim sets `NODE_PATH` to the virtual store, so member requires (`page-context`, `site-nav-tree`, `soft-nav-page-toc`, `link-validator`, …) resolve without a direct hub pin.

[cols="1,2",options="header"]
|===
| Piece
| Provided how

| Extensions (page-context, site-nav-tree, soft-nav-page-toc, nav-typology, link-validator, linkinator, page-edit, search-chat, …)
| **Pack members.** Do not pin or topic-tag them in the hub. Version bumps arrive by bumping the pack.

| Valentus UI bundle
| **Not an npm dependency of the pack.** It is a release asset (`ui.bundle.url` in the playbook). The pack does not set the URL; the playbook still names it. Treat it as the pack's *paired theme*, not a member extension — the hub carries no separate `valentus-theme` topic.

| `supplemental-ui` partials / helpers / CSS
| **Copied once** from the member packages (`ui/` folders) into the hub; the copies are hub-owned. Re-sync from `node_modules/.pnpm/…` or the member repos when a member bumps UI files.

| Maint CLIs (orphan-finder, nav-drift, stale-page, playbook-pin-auditor, deep-link-contracts)
| **`facto-maint <tool> …`** — the pack's `bin`. Hub scripts become `facto-maint orphan-finder --root ./docs …` with no extra pins.
|===

=== soft-nav-page-toc vs hub `soft-nav.js`

Two different things share the "soft nav" name:

* `@antora-supplemental/soft-nav-page-toc` is a **build-time Antora extension** (pack member). It adds compose-time nav-hidden meta and breadcrumbs and can inject a script that rebuilds the right-hand *page TOC* after a SoftNav swap.
* `supplemental-ui/js/soft-nav.js` is the **in-browser SoftNav script** copied from https://github.com/antora-supplemental/antora-ui-chassis/tree/main/packages/soft-nav[antora-ui-chassis]. It does the actual content swap on link clicks. Hub copies already rebuild the aside TOC, so hubs set `softNavPageToc: { injectScript: false }`.

The extension is a package you get through the pack; `soft-nav.js` is a file the hub owns. Neither replaces the other.

== Why a separate pack (not Valentus “full”)

Valentus stays lightweight so theme-only adopters are not scared off.
Facto is discovered **by pack name** (like a VS Code extension pack): theme + the other extensions you usually want, without folding those extras into Valentus core.

== Version pins (git)

Hub `package.json` should declare the compose pack once. Until npm publish, use a GitHub ref:

[source,json]
----
"@antora-supplemental/facto-stack": "github:antora-supplemental/facto-stack#v0.2"
----

* **`#v0.2`** (recommended) — rolling **minor line**: inherit v0.2.x patches when the pack ships fixes; opt into new minors by moving the pin (for example `#v0.3`).
* **`#v0`** — rolling **major line** within v0.x.x (minors + patches). Use when you accept minor-line moves without editing the pin.
* **`#v0.2.64`** — exact semver for bitwise CI or release notes you must match literally.

Rolling alias tags (`v0`, `v0.2`) are updated on every immutable release; see `supported-lines.json` for current heads. Immutable tags stay `vX.Y.Z`.

== Quick start

. Copy `playbook.fragment.yml` into your playbook (or start from `examples/minimal-playbook.yml`).
. `pnpm add github:antora-supplemental/facto-stack#v0.2 antora @antora/lunr-extension asciidoctor-emoji asciidoctor-kroki`
+
Or pin members individually until you adopt the pack: `pnpm add github:antora-supplemental/page-context#main github:antora-supplemental/page-edit#main github:antora-supplemental/link-validator#v0.2.0 github:antora-supplemental/linkinator#v0.1.0 github:antora-supplemental/extension-lister#v0.1.0`
+
Until build-stack is on npm: `pnpm add github:antora-supplemental/build-stack#main`
. Point `ui.bundle.url` at the Valentus `v2` release zip.
. Add brand/math/mermaid supplemental files as needed (see Valentus docs / org `supplemental-ui` patterns).

CI needs network access to `kroki-server-url` during `antora` when `kroki-fetch-diagram: true` (or self-host Kroki).

The fragment sets `page-context-active` so page bodies can keep `ifndef::page-context-active[]` fallbacks that stay hidden under Facto.

== Client Mermaid and diagram lightbox (supported options)

Facto fragment defaults still document **bake** (Kroki) for hubs that want build-time SVG.
The **published stack demo** uses the client path below — preferred when you want source-in-HTML + CDN runtime + lightbox without folding those into Valentus.

=== Client Mermaid (`@antora-supplemental/mermaid-client`)

. `pnpm add github:antora-supplemental/antora-diagram-engines#main&path:packages/mermaid-client`
. Playbook:
+
[source,yaml]
----
antora:
  extensions:
    - require: '@antora-supplemental/mermaid-client/antora'
      injectAssets: true
asciidoc:
  attributes:
    mermaid-client: ''
    mermaid-client-mode: client
----
. Include once in supplemental UI (after SoftNav for scripts):
+
----
{{> mermaid-client-styles}}
{{> mermaid-client-scripts}}
----
. Author ordinary `[source,mermaid]` listings (or `[.mermaid-client]`). PlantUML can still use `asciidoctor-kroki`.

Package tip includes the `register({ config })` fix so `injectAssets` keeps Antora's this-binding (`eee9e35`+: stem on injected partials; includes `register({ config })`).

=== Diagram lightbox (`@antora-supplemental/diagram-lightbox`)

. `pnpm add github:antora-supplemental/antora-diagram-engines#main&path:packages/diagram-lightbox`
. Playbook: `- require: '@antora-supplemental/diagram-lightbox'` (`injectAssets: true` default).
. Partials: `{{> diagram-lightbox-styles}}` / `{{> diagram-lightbox-scripts}}` (scripts after SoftNav).
. Prefer this over vendoring chassis `diagram-zoom` into hubs for new Facto demos.

=== PlantUML dark mode (demo vs ideal)

* **Ideal:** render light + dark from the diagram engine, then run `@dev-centr/plantuml-svg-css-vars` into https://github.com/dev-centr/themed-svg[Themed SVG] adaptive + host artifacts (same pipeline as hub docs). Serve with `[.themed-svg]` and host CSS (`demo/supplemental-ui/css/site-themed-svg.css`).
* **Today on the demo lightbox page:** committed Themed SVG from `pnpm diagrams:demo-plantuml` (Kroki fetch → adapter). Raw `[plantuml]` Kroki blocks stay fixed-color — use the script path for dark-mode-safe figures.
* **CI:** `pnpm diagrams:check` + Antora extension `demo/lib/verify-themed-svg-dark-mode.js` with `FACTO_THEMED_SVG_FAIL=1` (namespaces `facto-stack-demo-*` only).

=== SoftNav (chassis)

Copy https://github.com/antora-supplemental/antora-ui-chassis/tree/main/packages/soft-nav[`soft-nav.js`] into `supplemental-ui/js/` and load it **before** Mermaid / lightbox scripts (see `demo/supplemental-ui`).
